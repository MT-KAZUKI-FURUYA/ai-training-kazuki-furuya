# Day 08

## 受講者が実装する場所

- `day08/app.py` の `run_graph()`

## 目的

- 失敗時に復帰できるフロー（リトライ/フォールバック）を実装できるようにする
- 無限ループを防ぐ上限設計を入れられるようにする

## ゴール（完了条件）

- 失敗ケースでリトライ/フォールバックが動く
- 上限到達時に無限ループせず終了する

## 機能要件

コマンド

- `python -m day08.app` で起動できること（モジュール名は固定）

必須オプション

- `--text`：ユーザー入力（文字列、必須）

任意オプション

- `--max-steps`：最大ステップ数（整数、デフォルト `10`、1〜50）
- `--max-retry`：最大リトライ回数（整数、デフォルト `1`、0〜5）

出力

- 正常時：標準出力に結果（文章）を出す
- 失敗時：標準エラーにエラーメッセージを出す

終了コード

- 正常終了：`0`
- 入力不備：`2`
- 実行失敗（上限到達含む）：`1`

受け入れ基準

- 失敗ケースでリトライ/フォールバックが動く
- 上限到達時に無限ループせず、明示的に終了する


```bash

```

## リサーチメモ（任意）

調べたURLや、理解した要点をメモしてください。

- リトライ設計（何を再試行するか）：
  - JSONパースに失敗した場合、回答生成処理（`generate`）からやり直す。
  - 今回は `--text "不完全なJSONを返して"` の初回だけ壊れたJSONを生成し、2回目以降は正しいJSONを生成することで、リトライ成功パターンを確認できるようにした。
  - 再試行回数は `max_retry` で制限する。

- フォールバック設計（縮退動作、聞き返し）：
  - 検索ヒットなしを想定した場合、通常回答を無理に作らず、ユーザーに条件変更を促す案内文を返す。
  - 今回は `--text "存在しない情報について教えて"` のような入力で検索ヒットなしを再現する。
  - 何も返さず失敗するより、ユーザーが次に何をすればよいか分かる。

- 上限（最大回数、最大ステップ）：
  - `max_retry` は、JSONパース失敗時の再試行回数の上限として使う。
  - `max_steps` は、`generate`、`parse`、`search` など処理全体のステップ数の上限として使う。
  - `max_retry` は局所的な安全装置、`max_steps` は全体の安全装置として使う。
  - 上限に達した場合は例外を発生させ、`main()` 側で終了コード `1` の実行失敗として扱う。
  - これにより、失敗が続いても無限ループしない。

- 外部依存は追加せず、標準ライブラリの `json` のみで復帰パスを確認できるようにした。

- JSONパースとは、JSON形式の文字列をPythonで扱えるデータに変換すること。
  - 例：`'{"answer": "Pythonについて教えて への回答です。"}'` という文字列を `json.loads()` で読み込むと、`parsed["answer"]` のように値を取り出せる。
  - JSONの閉じカッコがないなど形式が壊れている場合、`json.JSONDecodeError` が発生する。

 
日常的なシステムでの利用イメージ：
- 決済システムで通信が一時的に失敗した場合に、すぐ数回だけ再試行し、それでも失敗したら利用者に案内する。
- 配送状況検索で該当データが見つからない場合に、別条件で探す、または番号確認を促す。
- AIチャットやエージェントで、AIの返答が壊れたJSONだった場合に、正しい形式で再生成させる。
- 外部API、検索、LLM呼び出しなど、失敗する可能性がある処理を安全に扱うために使う。

非エンジニア向けの説明：
今回の実装は、質問に回答する処理に「失敗したときの立て直し方」を追加したもの。
回答の形が壊れていた場合は、すぐに失敗せず、決められた回数だけ作り直す。
検索しても情報が見つからない場合は、空の結果で終わらせず、質問条件の変更を促す案内文を返す。
また、何度も処理を繰り返して止まらなくならないように、処理全体の回数にも上限を入れている。


## 付録：復帰パスの設計メモ

### 復帰パス（リトライ/フォールバック）

- 失敗パターン：JSONパース失敗、検索ヒットなし
- 復帰方法：JSONパース失敗時は再生成してリトライし、検索ヒットなし時はフォールバック文を返す
- 上限（最大回数/最大ステップ）：`max_retry` で再試行回数を制限し、`max_steps` で全体のステップ数を制限する
