# Day 05

## 受講者が実装する場所

- `day05/app.py` の `answer_with_rag()`

## 目的

- 公開データを使ってRAGの最小構成を作る
- 回答に根拠（出典）を必ず付ける

## ゴール（完了条件）

- `Answer:` と `Sources:` が必ず出力される
- ヒットなしの場合でも `Sources:` に `- (none)` が出る

## データ出典/ライセンス

- データ名：RAG説明用サンプルデータ（`day05/data/sample.txt`）
- URL：なし（研修課題の動作確認用に作成した自作テキスト）
- ライセンス：CC0 1.0（自由に利用可）

## 機能要件

コマンド

- `python -m day05.app` で起動できること（モジュール名は固定）

データ配置

- `day05/data/` 配下に、取り込むドキュメントを配置する
  - 形式はテキスト（`.txt`）でOK
  - 公開データから取得した本文を貼り付けてもよい

必須オプション

- `--question`：質問（文字列、必須）

出力（標準出力）

以下の形式で出力してください。

1. `Answer:` 行に回答
2. `Sources:` の下に参照元を列挙（最低1件）

例：

```
Answer: ...
Sources:
- <URL or ファイル名> (excerpt: "...")
```

検索ヒットなし時

- `Answer:` は「該当する根拠が見つからない」旨を返す
- `Sources:` は空にせず、代わりに `- (none)` を出す

終了コード

- 正常終了：`0`
- 入力不備：`2`
- 実行失敗（データ読み込み失敗等）：`1`

## リサーチメモ（任意）

調べたURLや、理解した要点をメモしてください。

- 本格的なRAGでは「分割、埋め込み、検索、プロンプトへの注入、LLMによる回答生成」を行うが、今回の課題では最小構成として「テキスト読み込み、段落分割、キーワード検索、根拠付き回答」を実装すれば要件を満たせると理解した。
- RAGは、まず文書を小さな単位に分割し、質問に近い情報を検索して、その情報を回答の材料として渡す流れだと理解した。今回は埋め込みとLLMへのプロンプト注入は使わず、段落分割とキーワード検索で最小構成を作った。`excerpt` を回答と出典に入れることで、検索結果を回答に反映する部分を確認した。
- 検索結果がない場合でも、プログラムが失敗したように見えない出力にすることが重要だと理解した。今回は `Answer:` に根拠が見つからないことと次の行動を表示し、`Sources:` には空欄ではなく `- (none)` を出すことで、正常に処理されたヒットなし状態だと分かるようにした。
- RAG：Retrieval-Augmented Generation の略。  
回答を作る前に外部データを検索し、その検索結果を根拠として回答する考え方だと理解した。
- Retrieval（検索）：質問に関係しそうな文書や段落を探す処理。  
今回は埋め込み検索ではなく、質問語が本文に含まれるかを見るキーワード検索で代用した。
- Augmented（補強）：検索で見つけた情報を回答に使えるように追加すること。  
今回はヒットした段落の抜粋を回答文と `Sources:` に入れることで、回答を根拠で補強した。
- Generation（生成）：検索結果をもとに回答文を作る処理。  
今回はLLMを使わず、「見つかった根拠では、...」という固定文に抜粋を組み込む形にした。
- Source（出典）：回答の根拠になった情報の場所。  
今回は `day05/data/sample.txt` のようなファイル名と、本文の一部である `excerpt` を出典として表示した。
