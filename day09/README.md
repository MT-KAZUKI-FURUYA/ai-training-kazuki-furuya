# Day 09

## 受講者が実装する場所

- `day09/app.py` の `load_suite()`
- `day09/app.py` の `run_case()`

## 目的

- 最低限の評価（テスト入力セット）を作り、改善前後の差分を説明できるようにする

## ゴール（完了条件）

- テスト入力セットを `--suite` で実行できる
- 結果JSONを `--out` に出力できる

## 機能要件

コマンド

- `python -m day09.app` で起動できること（モジュール名は固定）

必須オプション

- `--suite`：テスト入力セットのパス（必須）

任意オプション

- `--out`：評価結果の出力パス（デフォルト `day09/result.json`）
- `--timeout-sec`：1ケースあたりのタイムアウト（整数、デフォルト `30`）

出力

- 正常時：標準出力にサマリ（成功/失敗件数）を出す
- 失敗時：標準エラーにエラーメッセージを出す

終了コード

- 正常終了：`0`
- 入力不備（`--suite` 不正など）：`2`
- 実行失敗：`1`

受け入れ基準

- `--suite` で指定したケースを順に実行できる（まだ中身はスタブでもよい）
- `--out` にJSONを出力する（成功/失敗の一覧を含める）

## 実装タスク

- `day09/app.py` の `load_suite()` と `run_case()` を実装し、機能要件を満たす
- テスト入力セットを作成し、実行結果を記録する

### 今回の修正で理解したこと

- Day09は、AIの回答そのものを改善する課題というより、評価を実行して記録するための土台を作る課題だと理解した。
- `suite.json` は、評価したい入力ケースをまとめて保存しておくファイルである。
- `result.json` は、実行後の成功/失敗、理由、出力内容を保存しておくファイルである。
- `--suite` は「どのテスト入力セットを使うか」を指定するためのCLIオプションである。
- `--out` は「評価結果をどのファイルに保存するか」を指定するためのCLIオプションである。
- JSONはAPIの返答だけでなく、テスト入力セット、設定、評価結果、ログのようなデータ保存にも使える。

### テストケース設計

- 評価を作るとは、入力ケースを用意し、同じ手順で実行し、成功/失敗と理由を記録できるようにすること。
- 正常系：想定どおりの入力で最後まで処理ができる
- 異常系：ファイルなし、不正JSON、必須キー不足などの入力不備で失敗できる
- 境界：長文、記号、改行、空文字など、通常より壊れやすい入力でもクラッシュしない
- 再実行確認：同じsuiteを複数回実行しても結果JSONの形式が崩れない

### 評価の記録方法

- 標準出力には、人がすぐ確認できるサマリとして `passed=4 failed=1 total=5` を出す。
- `result.json` には、あとから見返したり比較したりできる詳細結果を保存する。
- `summary` には成功数、失敗数、合計数を入れる。
- `results` には各ケースの `id`、`passed`、`reason`、`output`、`duration_ms` を入れる。
- READMEには、実行コマンド、成功/失敗の集計、失敗の分類、確認した観点を文章で残す。
